🛠️ 設定のしかた

GitHub のトークンを作る（2 分）
  1. GitHub → 右上のアイコン → Settings → Developer settings → Personal access tokens
  2. Fine-grained: Repository access = kouchift/tokyostation、Permissions = Administration: Read-only（トラフィックの読み出しに必要）／ Classic: scope repo
  3. 有効期限は 90 日程度に。上の欄に貼って「取得する」。トークンはこのブラウザの localStorage にだけ入ります（共有 PC では「保存」を外す）
  4. ※ アップローダーの uploader/はじめに読む.txt のトークンは 公開サイトに載っています。必ず失効させて作り直し、GitHub 上の uploader/ フォルダを消してください（v93 で今後は上げない設定にしました）
全訪問者の «使われ方» を集める（いちばん簡単: tools/stats_deploy.bat をダブルクリック）
  1. tools/stats_deploy.bat をダブルクリック。あとは画面の指示どおり（初回だけ Google ログイン・Apps Script API を ON・最後に 1 回だけブラウザで «許可»）
  2. 自動でやること: 受け皿（tools/stats_api.gs）の作成・公開・data/analytics.js の endpoint への書き込み・アップロード・この管理ページを URL とキー入りで開く、まで
  3. スプレッドシートは自分で用意しなくてよい（初めて出来事が届いたときに «TSG 使われ方（東京ステーションガイド）» という名前で自動的にできる）
手でやる場合（スクリプトが使えないときだけ）
  1. script.google.com → 新しいプロジェクト → tools/setup_stats_backend.gs（こちらは要 SHEET_ID 書き換え）か tools/stats_api.gs（__ADMIN_KEY__ は好きな文字列か空に）の中身を貼る
  2. デプロイ → 新しいデプロイ → ウェブアプリ → 実行ユーザー「自分」・アクセス「全員」→ URL（…/exec）を控える
  3. data/analytics.js の endpoint にその URL を入れてアップロード → サイトが匿名の出来事を送り始める
  4. 上の「集計 API の URL」に同じ URL を入れて「取得する」

送られるのは 出来事の名前・短いラベル（駅名など）・ページ・参照元ドメイン・画面の区分・ブラウザの種類・言語・訪問ごとの乱数 だけ。氏名・メール・位置情報・端末 ID・IP は記録しません（Apps Script は IP を受け取れません）。訪問者はブラウザの「追跡しない」か 設定パネルで送信を止められます。

読み方

GitHub の「views」= ページの表示回数、「uniques」= 訪問者数（GitHub の推定、14 日分だけ保持）。サイト内の出来事は表示回数（pv）と訪問（sid）を分けて数えます。二つは数え方が違うので一致しません。
