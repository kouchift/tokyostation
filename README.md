# 東京ステーションガイド

東京23区とその周辺の **鉄道708駅・77路線** を、路線図から1タップで。
駅のスペック・駅構内の乗車位置・街のサマリを見て、そのまま
**徒歩／シェアサイクル／バス／電車／タクシー／レンタカー／レンタルバイク** を
時間と費用で並べて比べられる移動ダッシュボードです。

中村橋駅（西武池袋線）を中心に据えた夏休みの自由研究として作りました。

---

## 1. すぐ試す

`standalone.html` をブラウザで開くだけ。サーバーもインターネット接続も不要です。
分割版（`index.html`）を使う場合は、`python3 -m http.server` などローカルサーバー経由で開いてください
（現在地の取得と駅データの遅延ロードにHTTPが必要です）。

---

## 2. できること

### 2.1 路線図がすべての入口
- TOPは `100dvh` 固定、縦スクロールなし。ヘッダ／出発バー／路線図／フィルタの4段。
- 下層ページは持たず、駅の情報はすべてカード内で完結。
- ズームに応じてラベルを間引く（LOD）ので、708駅でも文字が潰れません。
- 駅カードの「となりの駅」チップをタップすると路線をたどって移動できます。

### 2.2 駅カードの中身

| 層 | 内容 | 出どころ |
|---|---|---|
| L1 | 駅名・乗り入れ路線・一言サマリ | ネットワークデータから自動生成 |
| L2 | **駅のスペック**（乗降人員と順位／路線数／ホーム数／開業年と古さ順位／徒歩圏の他駅） | Wikidata＋計算 |
| L3 | **駅構内** — 何号車に乗れば階段・EV・乗換が近いか | 現地調査（手入力） |
| L4 | **混雑のめやす** | 現地調査。無ければ乗降人員から推定 |
| L5 | **街のサマリ** — 食べる／見る・歴史／景色 | 現地調査（手入力） |

L2の「一言サマリ」は数値から自動生成されます。例：
> 5番目に人が多い巨大ターミナル。10路線が集まる結節点。徒歩数分に別の駅が4つあり、迂回ルートを作りやすい。

### 2.3 出発地と時刻を宣言する

| ボタン | 動作 |
|---|---|
| 📍 現在地 | Geolocation API（**HTTPS または localhost のみ**。ファイル直開きでは使えません） |
| 駅カードの「📍 ここから出発」 | その駅を出発地に |
| 日時 | 今すぐでも未来の予定日時でもOK |
| 🛡️/⚖️/🔥 | **アグレッシブ度**。徒歩・自転車の上限距離と提案のトーンが変わります |

出発地を決めると、全708駅が到達時間で色分け（等時線）されます。

### 2.4 比較ビュー（駅カードの「🧭 ここへ行く」）

横軸＝所要時間、縦軸＝費用の散布図。**青い破線がパレート最適**（それより速くて安い手段が無い選択肢）。
線より上の点は「時間でも費用でも他に負けている＝選ぶ理由がない」と一目で分かります。

各案に「最安より◯分速い／+◯円（1分あたり◯円）」を表示するので、**コスパの傾き**が数値で見えます。

### 2.5 🌙 深夜レスキュー — このサイトの独自性

出発時刻が **終電〜始発の窓（既定 00:30〜05:00）** に入ると自動で深夜モードになり、

- 電車の案は「いまは運休の時間帯」として**降格**され、代わりに次の案が上位に来ます。

| 案 | 内容 |
|---|---|
| 🌅 **始発を待つ** | 「あと◯分待てば、◯◯円で帰れる」を明示 |
| 🚕🚶 **タクシー◯%＋徒歩** | 途中で降りて歩く。「タクシー全区間より◯円節約」を表示 |
| 🚕🚲 **タクシー◯%＋シェアサイクル** | 同上、残りを自転車で |
| 🚲🌙 **深夜の自転車リレー** | 電車が動いていなくても使える |
| 🚶🌙 **歩ききる** | 0円。始発を待つより早いかどうかの判断材料 |

さらに「🌙 終電を逃した」ボタンから **予算スライダー** が開きます。
タクシーに出す金額を動かすと、**何km圏／何駅が射程に入るか**、
そこから自転車・徒歩でどこまで伸ばせるかが同時に更新されます。

実例（渋谷→中村橋・AM4:00・🔥攻めるモード）:

| 案 | 時間 | 費用 |
|---|---|---|
| 🚕 タクシー | 35分 | ¥7,200 |
| 🚕🚲 タクシー55%＋シェアサイクル | 54分 | ¥4,356（**¥2,844節約**） |
| 🚲🌙 深夜の自転車リレー | 66分 | ¥693 |
| 🚶🌙 歩ききる | 163分 | ¥0 |
| 🌅 始発を待つ | 99分 | ¥430（**いちばん安い**） |
| ~~🚃 電車~~ | ~~39分~~ | いまは運休の時間帯 |

「上京したてでも迷わない」ための設計です。東京の土地勘がなくても、
**何円出せばどこまで帰れるか**が数字と地図で同時に分かります。

### 2.6 行き先をさがす

目的地が決まっていないとき用。「ここから30分以内」×気分タグ
（🍜 おいしいもの／⛩️ 歴史・名所／🌇 景色／🏙️ 大きい駅／🌿 静かな駅／🧭 まだ誰も調べてない駅）
で候補駅を採点し、路線図上でも光らせます。

**🧭「まだ誰も調べてない駅」**は `data/details/` にファイルが無い駅へ自動で付きます。
行き先探しの導線が、そのまま**次に調査すべき駅のリスト**になります。

## 3. データの出どころと確信度

| 項目 | 出典 | ライセンス／確信度 |
|---|---|---|
| 駅名・かな・緯度経度・乗り入れ路線・隣接関係・ホーム数・開業年・1日平均乗降人員 | **Wikidata** (SPARQL, 2026-08-30取得) | **CC0 1.0**（パブリックドメイン）／確信度：中 |
| タクシー運賃 | 東京特別区・武三地区 2026年4月20日改定：初乗り500円/1.0km、加算100円/232m、改定率10.14% | 高 |
| 都営バス運賃 | 東京都交通局 23区均一 大人210円 | 高 |
| シェアサイクル | ドコモ・バイクシェア 30分165円／**2026年9月1日からNOLL新料金 10分99円**（日付で自動切替） | 高 |
| JR運賃 | 2026年3月14日改定。電車特定区間・山手線内を廃止し幹線へ統合、初乗り160円 | 初乗りのみ高 |
| 徒歩速度 | 不動産の表示に関する公正競争規約（分速80m） | 高 |

### ⚠ 信用してはいけない部分（UIにも常時表示しています）

| 項目 | 問題 |
|---|---|
| **Wikidataの数値全般** | 誰でも編集できるデータです。乗降人員は事業者・年次・集計方法（乗車人員/乗降人員）が混在している可能性があります。「登録のある事業者ぶんの合計」であり、その駅の総数とは限りません |
| **鉄道運賃テーブル** | 初乗り以外は推定値。直通運転時の通算運賃も考慮していません |
| **時刻表** | 持っていません。終電・始発（00:30／05:00）は首都圏のおおよその目安で、駅・路線ごとの実際の時刻ではありません |
| **バス** | 系統データがありません。「直線距離÷バス速度」であり、直通路線の有無は未確認 |
| **シェアサイクル** | ポート位置データがありません |
| **都電荒川線** | Wikidataの隣接データが欠けており、路線が分断されています |
| レンタカー／バイク | 事業者・車種で大きく変動。確信度：低 |

すべて「概算モデル」です。移動前に各事業者の公式情報で必ず確認してください。

### 著作権の扱い方

方針：**出所とライセンスが明示され、その条件を守れるものだけを採用する。**

| 種類 | 判断 |
|---|---|
| Wikidata | ✅ 採用。CC0（パブリックドメイン）で条件なし。それでも出典を明記 |
| 数値・事実データ（運賃、駅名、駅順） | ✅ 採用。**事実は著作権の対象外**。表現をコピーせず自分のデータ構造に書き直して出典を付す |
| 路線図の図版 | ❌ 不採用。座標から自前で描画 |
| ラインカラー | ⚠ 「本アプリの表示色」として実装。公式ラインカラーとは限りません |
| 個人サイトの「著作権フリー」図版 | ⚠ ライセンス名（CC0/CC BY/ODbL等）と元データの出所が**両方たどれる**場合のみ採用し、出典をサイト内とREADMEの両方に明記 |

「著作権フリー」表記そのものは法的な保証になりません。掲載者に権利がないケース
（公式路線図のトレース等）が実際に多いためです。条件を満たせない場合は、
**事実データだけを読み取って自分で作り直す**のが確実な回避手段です。本プロジェクトはその方針です。

条件が明確な代替データ：国土数値情報（国土交通省・出典明示で利用可）、
OpenStreetMap（ODbL・「© OpenStreetMap contributors」表示が必要）、
公共交通オープンデータセンター ODPT（要APIキー・時刻表あり）。

## 4. 拡張のしかた

### 路線・駅を増やす
`tools/build_network.py` を実行し直すだけです。取得範囲を広げたい場合は
SPARQLのバウンディングボックス（経度139.54–139.94、緯度35.49–35.85）を変更して再取得してください。
西武池袋線の区外区間（所沢〜吾野）を含めたいときは `INCLUDE_SEIBU_TAIL = True` にします。

### 駅の調査データを足す
`data/details/<駅名>.js` を置くだけ。タップされたときに初めて読み込まれ、
無ければ「未調査」と表示されるだけで壊れません。ひな形は `data/details/_TEMPLATE.js.txt`。

```
data/details/富士見台.js  →  富士見台駅のカードに号車ゲージ・混雑・街サマリが出る
```

### 計算の前提を変える
`data/config.js` に、速度・迂回率・運賃・終電時刻・アグレッシブ度がすべて
`source`（出典）と `conf`（確信度）付きで集約されています。

## 5. モバイル対応

| 課題 | 対策 |
|---|---|
| ホバーが無い | `@media (hover:hover)` で分岐。タップ→ボトムシート（2段スナップ） |
| 708駅の描画負荷 | 路線を色ごとに1本のpathへ集約（67path）。ラベルはズーム連動で間引き |
| タップ精度 | 駅ノードに半径11（≒44px相当）の透明ヒット領域 |
| 画像 | 0個（CSSグラデーションで代用） |
| 縦スクロール | TOPは `100dvh` 固定 |
| 動きが苦手な人 | `prefers-reduced-motion` 対応 |
| キーボード操作 | 主要駅は `tabindex` + Enter/Space、`:focus-visible` 明示 |
| 深夜 | 深夜モードで配色が暗転（夜間の視認性） |

## 8. この駅の「戦闘力」— 総合スコアとレーダーチャート

駅カードの上段に、**23区708駅の中での相対評価**をレーダーチャートで表示します。
中心の大きな数字が総合スコア（0〜100）と S/A/B/C/D ランク、右上に順位が出ます。

| 軸 | 中身 | データ源 |
|---|---|---|
| 🚉 交通力 | 乗り入れ路線数・乗降人員・徒歩圏の他駅数 | Wikidata |
| 🏛️ 歴史・文化財 | 国宝10点／重要文化財6点／史跡5点／登録有形3点…と重みづけした合計 | Wikidata |
| ⛩️ 社寺仏閣 | 神社・寺院・教会の件数 | Wikidata |
| 🌳 くらし・公共 | 図書館・公園・病院・大学・博物館・美術館 | Wikidata |
| 💰 地価のやさしさ | 公示地価の中央値（安いほど高得点） | 国土数値情報 L01 |
| 🌙 終電後の帰りやすさ | 主要ターミナルからの近さ＋路線数 | 計算 |

集計範囲はすべて **駅から徒歩10分（800m）圏**（分速80m × 10分）。
各軸は生の数値ではなく **708駅中のパーセンタイル順位** に直しているので、
「東京の中でどのくらいか」がそのまま読めます。

実測例：

| 駅 | 総合 | 順位 | 🚉 | 🏛️ | ⛩️ | 🌳 | 💰 | 🌙 |
|---|---|---|---|---|---|---|---|---|
| 上野 | **84** | 1位 | 100 | 99 | 97 | 97 | 13 | 99 |
| 浅草 | 77 | 19位 | 97 | 90 | 99 | 59 | 21 | 99 |
| 九段下 | 74 | 30位 | 87 | 94 | 53 | 98 | 8 | 95 |
| 新宿 | 58 | 174位 | 100 | 0 | 39 | 95 | 3 | 99 |
| 舎人 | 42 | 361位 | 19 | 0 | 85 | 35 | **100** | 24 |
| 中村橋 | 29 | 547位 | 4 | 0 | 14 | 35 | 87 | 36 |

中村橋が547位なのは正直な結果です。**地価87点（＝安い）** が効いていて、
「便利さは平均以下だが、住むには手が届く」という素直なポジショニングが読み取れます。

### 評価軸を足す設計

`data/score.js` の配列に1エントリ足すだけで、レーダーの頂点・順位・総合スコアが自動で追従します。

```js
{ id:"newaxis", label:"新しい軸", emoji:"🆕", color:"#0055AD",
  weight:1.0, dir:1, enabled:true,
  desc:"説明", raw:function(station, poi){ return 数値; } }
```

未実装の軸（🛒買い物・🍜外食・🏋️ジム・美容・📚学び）は `enabled:false` で定義済みです。
カード内に「未実装の評価軸 4件」として理由つきで表示され、データが手に入り次第
`enabled:true` にするだけで有効化できます。

### 文化財の絞り込みについて
Wikidataの「重要文化財」には、刀剣・絵画・古文書などの**動産（美術工芸品）**も
座標つきで登録されています（例：東京国立博物館の収蔵品）。
これらを含めると上野周辺のスコアが実態から乖離するため、
**建造物・史跡だけを残し、動産137件を除外**しました（`tools/build_poi.py` の `MOVABLE`）。

### 画像のライセンス
各画像の下に「📷 Wikimedia Commons — CC BY-SA 4.0 / 作者名」を表示し、
クリックでCommonsのファイルページ（作者・ライセンス全文）へ飛びます。
1,834ファイル分のライセンス情報をCommons APIから取得済みです。
**再配布する場合は、ファイルごとのライセンス条件を必ず確認してください。**

## 11. ⚠ できなかったこと（正直に）

### 11.1 鉄道会社のロゴ・シンボルマーク・キャラクター画像は同梱しません

**ロゴ・シンボルマークの画像そのものは収録していません。** 理由は3つです。

1. **法的な理由**：ロゴ、路線シンボルの意匠、マスコットキャラクターは著作権と商標権の
   両方で保護されています。東京メトロは
   [コミュニケーションマーク等使用ガイドライン](https://www.tokyometro.jp/support/trademark/pdf/guideline.pdf)
   を公開しており、使用には許諾の手続きが定められています。
2. **パスワードで隠しても変わらない**：公開されたサイトに含まれている限り、
   ログインゲートの有無は権利関係を変えません。むしろ「権利者に見つからないように隠す」
   という発想は、自由研究の作法としても勧められません。
3. **そもそも取得できない**：ロゴやキャラクター画像は、Wikidata / Wikimedia Commons など
   自由に使えるデータセットに入っていません（入っていれば使えます）。

**その代わり、「見慣れた色味とアイコン」は法的に問題なく再現できます。**

| 要素 | 扱い |
|---|---|
| **ラインカラー** | ✅ 採用。色（数値）は各社が案内のために公表している情報で、著作物ではありません。メトロ9線・都営4線・JR主要線・東急・京王など**58路線を公表色で再現** |
| **路線記号（G・M・JY・SI など）** | ✅ 採用。識別子であり文字そのものは著作物ではありません。バッジの図形は**本アプリが独自に描画** |
| **ロゴ・シンボルマーク・キャラクター画像** | ❌ 同梱しません |

### 11.1.1 🔒 シークレットモード

設定（⚙️）から合言葉を入れると、次の2つが有効になります。

- 路線記号バッジの**塗りつぶし拡大表示**（見慣れた案内サインに近い見え方）
- **持ち込みアイコン**：`assets/logos/<路線名>.png` を自分で置くと、そのファイルが路線アイコンとして使われます

合言葉は `nakamurabashi` です（`assets/lines_ui.js` に簡易ハッシュで入っています。
強度は求めていません。ソースを読めば分かります）。

**持ち込みアイコン機能について**：これは「自分で用意した画像を使う」ための一般的な機能です。
アプリ側は画像をダウンロードも同梱もしません。
置いた画像の権利処理は**置いた人の責任**になります。学校での掲示など私的・教育的な利用と、
Web公開では条件が変わる点に注意してください。使いたい場合は各社の広報窓口へ利用許諾を申請するのが確実です。

### 11.2 コンビニ・スーパー・美容室・学習塾・ジム・チェーン飲食店の店舗数

**取得できませんでした。** 唯一の現実的なデータ源である OpenStreetMap Overpass API が、
作業時点で確認した**全ミラー（8か所）が停止・空データ**でした。

```
overpass-api.de     503    z.overpass-api.de      503
kumi.systems        502    lz4.overpass-api.de    503
private.coffee      500    monicz.dev             500
osm.jp              503    osm.ch                 200だが空DB
```

Wikidataには個店（コンビニ・美容室など）のデータがほぼありません。
そのため **軸の定義だけ置き、`enabled:false` で「データ未取得」と明示**しています。
Overpassが復旧すれば `tools/` にクエリを足して有効化できます。

### 11.3 「全国スーパー売上高ランキングベスト1000」「チェーン店売上ランキングベスト50」

**このランキングデータを持っていません。** 公開されている無料の機械可読データが見つからず、
推測でリストを作ると評価軸そのものが虚偽になるため、実装していません。
ランキングのCSVをお持ちであれば、ブランド名でOSM/独自データを突き合わせる形で組み込めます。

### 11.4 賃貸相場

民間データのため取得できません。代わりに **公示地価（国土数値情報）** を使っています。
地価と賃貸相場には相関がありますが**同一ではありません**。
「地価のやさしさ」という軸名にしているのはそのためです。

### 11.5 YouTube動画のサムネイル

**動画IDを推測で埋めることはしません**（存在しないURLになり、リンク切れを量産するため）。
YouTube Data API のキーがないため、動画の自動探索もできません。

実装したのは次の2つです：
- `data/details/<駅名>.js` の `videos: [{id:"...", title:"..."}]` に手で入れると、サムネイルが3件まで並ぶ
- 未登録の駅では「YouTubeで検索 ↗」リンク（駅名を引き継ぐ）

### 11.6 オフラインでの画像表示

`standalone.html` は単一ファイルで動きますが、**画像はWikimedia Commonsから読み込む**ため
ネット接続が必要です。完全オフラインにするには画像をローカルに保存する必要があり、
その場合はライセンス表示義務が発生します。

# v6：路線ランチャーと相対評価ダッシュボード

## 16. 🚀 路線ランチャー（駅カードの路線チップ）

駅名の下に並ぶ**路線チップを押す**と、その場で沿線の駅一覧が開きます。

```
[SI 西武池袋線 ▾]  ← 押す
┌──────────────────┬──────────────────┐
│ ▸ ひばりヶ丘 方面   │ ▸ 池袋 方面        │
│ ● 富士見台  1駅/1分 │ ● 練馬    1駅/3分  │
│ ● 練馬高野台 2駅/4分│ ● 桜台    2駅/5分  │
│ ● 石神井公園 3駅/7分│ ● 江古田  3駅/7分  │
│ ● 大泉学園  4駅/11分│ ● 東長崎  4駅/10分 │
│ …                 │ ● 椎名町  5駅/13分 │
│                   │ ● 池袋    6駅/16分 │
└──────────────────┴──────────────────┘
```

- **上り／下りを2列**に並べ、終点方向の駅名を見出しにします
- 各駅に「◯駅目 / 約◯分」を表示（表定速度32km/hでの概算）
- **駅名を押すとその駅へ即遷移**し、そこでまた路線チップを開ける → 何度でも乗り継げます
- 開くと同時に**路線図側もその路線を強調表示**します
- ⭐注視駅は一覧の中でも星つきで目立ちます

### 隣接データのノイズ対策

Wikidataの隣接（P197）には誤りが混ざります。そのまま辿ると
「練馬 → 東長崎 → 市場 → 江古田」のように順序が壊れました。対策として、

1. **進行方向の連続性** … 直前の進行方位にいちばん近い隣接だけを次の駅に選ぶ（逆走・直角の折返しを排除）
2. **距離の飛びを切る** … 直前の区間長の3.2倍または3kmを超える隣接は無視
3. **廃駅を除外** … Wikidata の P576（廃止年）と廃駅クラスから50件を特定し、ネットワークから削除

結果、西武池袋線は `中村橋 → 練馬 → 桜台 → 江古田 → 東長崎 → 椎名町 → 池袋` と正しく並ぶようになりました。
駅数は 708 → **672**（廃駅・信号場を除外）に整理されています。

### 隣接データが無い路線のフォールバック

Wikidataでは山手線の区間が「東北本線」として登録されているなど、
路線名と隣接データが噛み合わないケースがあります。その場合は
**「この路線の駅（近い順）」** として距離順のリストを出します。
順序の保証はありませんが、行きたい駅には必ず辿り着けます。

誤接続を防ぐため、両端点がその路線を持っていることを条件にしています。

## 32. 駅を最前面に

SVGの重ね順を明示的に分けました。


## 33. 各スポット・各駅の概要文

**716件**に概要文を付けました。駅カードとスポットカードの上部に出ます。

| 表示 | 出どころ | ライセンス |
|---|---|---|
| 一行の説明（例：「東京都練馬区にある西武鉄道の駅」） | Wikidata の description | **CC0 1.0**（パブリックドメイン） |
| 2〜3文の概要 | Wikipedia 日本語版の冒頭 | **CC BY-SA 4.0** |

### 取得のしかたについて（正直に）

ご提案は「検索すれば追える概要情報の要約だから著作権的に大丈夫」でしたが、
**事実は著作権の対象外でも、それを説明した「文章そのもの」には著作権があります。**
そこで、任意のサイトを回って要約する方法ではなく、次のようにしました。

1. **Wikidata の description（CC0）** — パブリックドメインなので条件なしで使えます
2. **Wikipedia 冒頭抜粋（CC BY-SA 4.0）** — MediaWiki の公式APIから取得し、
   カードに必ず「出典: Wikipedia 日本語版（CC BY-SA 4.0）」と記事へのリンクを表示

これなら**出どころが明確で、条件を守れて、しかも情報の質も高い**という三方よしになります。
個別サイトのスクレイピングは行っていません。

抜粋は3文・200字までに制限しています。もっと知りたいときは、
カード下部の「もっと詳しく調べる」から文化庁・東京都オープンデータ・国立国会図書館・
CiNii などの一次情報へ飛べます。

| 地下鉄の混雑の見える化（東京都交通局） | **PNG画像**のみで機械可読ではありません |
| 人口・統計データ | 位置情報が町丁単位で、駅ベースの本アプリと粒度が合いません |

いちばん惜しいのは**バリアフリー情報**です。駅ごとのエレベーター位置が構造化されれば、

# v13：現在地が取れないときの案内

## 40. まず正直に：Webページから設定画面は開けません

ご要望は「有効化するための設定箇所まで画面遷移してくれる実装」でしたが、
**Webページから OS やブラウザの設定画面を直接開くことは、どのブラウザでも許可されていません。**

- `chrome://settings/content/location` や `about:preferences` へは、
  ページ内のリンク・スクリプトからは遷移できません（ブラウザが遮断します）
- iOS の `App-Prefs:` や `prefs:root=` といったスキームも、Safari の Web コンテンツからは開けません
- Android の `intent://` で設定アプリを開くこともできません

これはブラウザの安全設計であって、実装で回避すべきものではありません。
そこで **「どこを何回タップすればよいか」を、その人の環境に合わせて正確に出す**方式にしました。

## 41. 失敗の理由を切り分ける

「許可していない」以外の原因も多いので、まず理由を判定します。

| 判定 | 表示するメッセージ | 直し方 |
|---|---|---|
| `file://` で開いている | ファイルを直接開いているため位置情報が渡らない | 設定では直せない。`python3 -m http.server 8000` の手順を表示 |
| `http://`（安全でない接続） | ブラウザが位置情報を渡さない | https か localhost が必要 |
| エラーコード1（拒否） | このサイトの位置情報がブロックされている | 許可の手順へ |
| エラーコード2（取得不可） | OS 側の位置情報サービスが切れている可能性 | OS 設定の手順へ |
| エラーコード3（タイムアウト） | 電波や GPS の状況 | 窓ぎわへ／Wi-Fi をオン／再試行 |

`navigator.permissions.query({name:"geolocation"})` が使える環境では、
**いまの権限の状態**（✅許可／⛔ブロック／❓未確認）も画面に出します。

## 42. 環境ごとの手順

UA から OS とブラウザを判定し、**その組み合わせの手順だけを最初に出します**。
検証した14通りすべてで正しく分岐しました。

| 判定した環境 | ①いちばん早い方法 | ②OS の設定 |
|---|---|---|
| iPhone / Safari・Chrome・Firefox | 各ブラウザの手順 | iPhone（iOS） |
| iPad / Safari | Safari の手順 | iPad（iPadOS） |
| Android / Chrome・Samsung・Edge・Firefox | 各ブラウザの手順 | Android |
| Mac / Safari・Chrome | 各ブラウザの手順 | Mac（macOS） |
| Windows / Edge・Chrome・Firefox | 各ブラウザの手順 | Windows |
| Linux / Chrome | Chrome の手順 | Linux |

**①いちばん早い方法**は、どの環境でも共通して効く「アドレスバーの鍵マーク → サイトの設定 → 位置情報」の近道です。
**②OS の設定**は、実際のメニュー名をたどった手順を書いています。例：

- **iPhone**：設定 → プライバシーとセキュリティ → 位置情報サービス → ブラウザを選ぶ →「このAppの使用中」
  ＋ Safari のときは 設定 → Safari → 位置情報
- **Windows**：設定 → プライバシーとセキュリティ → 位置情報 →「位置情報サービス」
  ＋「アプリに許可」＋**「デスクトップ アプリに許可」**（ここを忘れる人が多い）
- **Mac**： → システム設定 → プライバシーとセキュリティ → 位置情報サービス → ブラウザをオン
- **Android**：設定 → 位置情報 → オン ＋ 設定 → アプリ → ブラウザ → 権限 → 位置情報

**他の OS の手順**もすべて折りたたみで載せてあるので、
「家族の iPhone で見せたい」ようなときにも使えます。

## 43. そのほかの原因も明記

- プライベート／シークレット モードでは拒否されることがある
- VPN や広告ブロッカーが止めていることがある
- デスクトップ PC は GPS を持たないので Wi-Fi から推定する。有線 LAN だけだと数km ずれる
- 会社や学校の端末では管理者設定で禁止されていることがある

画面には「📍 もう一度ためす」と「🚉 かわりに駅を指定する」のボタンを置き、
どちらでも先へ進めるようにしています。
また、`http://` や `file://` で開いているときは、出発バーの「📍 現在地」ボタンが
最初から <b>⚠</b> つきの警告色になります。

取得に成功したときは、精度（`±◯m`）も表示するようにしました。

## 62. 共有した本文のURLがリンクにならない問題

原因は、URLが**行の途中**にあったことです。

```
before:  　📍 地図: https://www.google.com/maps/...      ← 全角スペース＋ラベルの後ろ
         ・Yahoo!路線情報（駅名入力ずみ）: https://...   ← 全角括弧とコロンの後ろ
```

多くのアプリ（LINE・メール・メモ帳など）の自動リンク化は、
**行頭から始まるURL**を最も確実に拾います。全角文字が直前にあると外すことがあります。

```
after:   　📍 地図で開く
         https://www.google.com/maps/...                ← 行頭に単独で置く

         ・Yahoo!路線情報（駅名入力ずみ）
         https://transit.yahoo.co.jp/...
```

**すべてのURLを行頭の単独行**に置き直しました（検証：行頭URL 6件／行途中URL 0件）。

あわせて `navigator.share()` に **`url` を渡す**ようにしました。

```javascript
navigator.share({ title, text, url: gmapRoute() })
```

LINE や X はこの `url` をリンクカードとして扱います。
`url` 付きを受け付けない実装もあるので、失敗したら `text` だけで再送する仕掛けも入れています。

## 64. 📍 現在地マーカー

| 要素 | 役割 |


## 69. 🧭 案内モード（カーナビ風のリルート）

比較ビューの各案に **「🧭 この道で案内」** を追加しました。

### 動き

1. 押すと `watchPosition` で現在地の追跡を始めます
2. 画面上部に**案内バー**が出ます（目的地・手段・のこり距離・ルートからのズレ・精度・進捗バー）
3. 現在地とルートの距離を毎回計算します
4. 離れすぎたら**一度だけ**確認します

```
🧭 ルートから外れています

いまの道は、はじめに決めたルートから 約1,631m 離れています。
ここから 練馬駅 まで案内し直しますか？
いまいちばん近い駅は 氷川台駅（約302m）です。

 [🔁 ここから案内し直す]
 [このまま進む — 寄り道中ならこちら]
 [🔕 この移動のあいだ、もう聞かない]
```

### うるさくしないための工夫

| 工夫 | 内容 |
|---|---|
| **2回続けて外れたときだけ**聞く | GPSが一瞬飛んだだけでは反応しません |
| **GPS精度を見て閾値を変える** | 精度±200mなら320m以上離れないと反応しません |
| **手段ごとに許容を変える** | 徒歩160m／自転車260m／バス320m／車400m／電車500m |
| **1分間は再確認しない** | 連続で出ません |
| **🔕 もう聞かない** | その移動が終わるまで完全に黙ります |
| 案内バーの🔕を押せば**再開**できます | 気が変わったとき用 |

「ルートから外れた」の判定は、現在地と**ルートの線分すべて**との最短距離です。
電車の案内なら通る駅を結んだ線、徒歩や車なら出発地と目的地を結んだ線を使います。

### 検証結果

```
ルート上を進む      → 警告なし ✓
1回だけ外れる       → 様子見（offCount=1）✓
2回続けて外れる     → 警告が出る ✓（約1,631m・最寄り氷川台駅302mも案内）
🔕 もう聞かない     → 以後どれだけ外れても黙る ✓
案内をやめる        → バーが消えて追跡停止 ✓
```

**電池のことも考えています。** `maximumAge: 8000` で8秒以内の測位は使い回し、
案内を止めれば `clearWatch` で追跡を完全に終了します。

- **カテゴリの絵文字**（🏪 ☕ 🍔 🍚 🥩 🍜）

店舗カードにも「お店のロゴは商標のため出せません。ブランドカラーで表しています」と明記しています。

ミラーの負荷が高く、重いパターンを処理しきれなかったようです。
単純な `ローソン|LAWSON` に変えたら一発で1,713件取れました。

未取得のブランド（イオン・ライフ・西友・マツキヨ・ダイソー・ニトリなど22社）は、

## 79. ヒートマップが切り替わらなかった原因

- **区ごとに数値を表示**（色だけでは読み取れないため）

- データが無い区は**薄いグレー**にして「ゼロ」と区別
- 凡例に **1位〜3位の区名と値**を表示

# v26：3Dが「反応しない」ように見えた原因

## 87. 原因は投影のズレでした

3Dボタンを押すと、地図の要素は**きちんと882個描かれていました**。
ところが**見えませんでした**。理由はこうです。

3Dでは「奥行きをつぶす」ために、縦方向の座標を約0.6倍にします。

```
2Dで y=800 の場所  →  3Dでは y=480 に移動
```

ところが画面が映していたのは `y = 754〜940` の範囲でした。
つまり **見ていた場所が、画面のはるか上へ飛び出していた**わけです。
図形は存在するのに、映っていない場所に描かれていました。

### 直しかた

**画面の中心が動かないように、ずれたぶんを戻す**計算を入れました。

```javascript
oy = 画面中心のy × (1 - 縮み率) + 画面の高さ × 0.10
```

最後の項は、建物が立ち上がる «空» を少し作るためのものです。

### 確認（中心の駅が画面のどこに来るか）

| 表示 | 3Dでの位置 | |
|---|---|---|
| 全体表示 | 画面の縦 55% | ✓ 画面内 |
| 上野・広域 | 59% | ✓ |
| 上野・地区 | 57% | ✓ |
| 中村橋・地区 | 48% | ✓ |
| 渋谷・拡大 | 47% | ✓ |

**どのズームでも、見ていた場所がほぼ画面の真ん中に来ます。**
地図を動かしたときも3Dが追従するようにしました。

## 88. 検証のやりかたを変えました

前回のCSSバグに続き、今回も**「要素は作られているか」しか見ていなかった**のが原因です。
数だけ見て「動いている」と判断していました。

今回から次の2つを検証に入れました。

## 126. 映像が見られなかった原因

**動画IDが途中で切れていました。**

```
before: https://www.youtube.com/watch?v=E2v6OIS6      ← 8文字（壊れている）
```

名前や住所には妥当でしたが、URLまで切れていたのです。

```python
if v: rec[key] = v[:40]                                 # ← 原因
if v: rec[key] = v[:200] if key == "url" else v[:40]    # ← 修正
```

再取得したところ、**94件すべてのIDが11文字**になりました。
これでYouTubeへ飛ばずに再生できます。

# v45：ボタンが効かなかった本当の原因

## 170. 原因は2つありました

### ① 地図のドラッグ処理が、ボタンのクリックを横取りしていた

地図は指やマウスで動かせます。そのために、押した瞬間に
**「以後の操作はぜんぶ地図が受け取る」** という設定をしていました。

```javascript
wrap.addEventListener("pointerdown", function (e) {
  if (e.target.closest(".node")) return;   // 駅の上なら地図は動かさない
  wrap.setPointerCapture(e.pointerId);     // ← ここで «横取り» が始まる
});
```

除外していたのは **駅（.node）だけ**でした。
色分け・3D・地形・浸水のボタンは**地図の上に重ねて置いてある**ため、
押した瞬間に横取りが始まり、**click がボタンに届きませんでした。**

```javascript
// 直したあと
var UI_SEL = ".quickbar,.heatlegend,.navbar,.chips,.poipop," +
             "button,a,input,select,textarea,label,[role=button]";
wrap.addEventListener("pointerdown", function (e) {
  if (e.target.closest(".node")) return;
  if (e.target.closest(UI_SEL)) return;    // ボタンの上なら地図は動かさない
  wrap.setPointerCapture(e.pointerId);
});
```

ホイールとタッチ操作にも同じ除外を入れました。
**ボタンの上でスクロールしても、地図が勝手に拡大しません。**

### ② バーを作り直すたびに、ボタンの «手» が外れていた

バーは押すたびに中身を作り直します。
そのとき、**前に付けた手（イベント）ごと捨てられて**いました。
タイミングによっては、作り直したあとのボタンに手が付いていない状態になります。

**親に一度だけ手を付け、押された場所から一番近いボタンを探す**方式に変えました。
作り直しても手が外れません。

```javascript
q.addEventListener("click", function (ev) {
  var b = ev.target.closest("[data-qb]");   // 押された場所から探す
  if (b) { …… }
});
```

## 171. なぜこれまで見つけられなかったか

わたしの点検では、ボタンに `click` を**直接送っていました**。
実際の操作は `pointerdown → pointerup → click` の順で起きます。
**`pointerdown` を送っていなかったので、横取りが再現しませんでした。**

今回から、点検でも**実際と同じ3つの手順で押します**。
`setPointerCapture` も本物と同じように働かせています。
